CompanyX control integration — new files only, 2026-11-05

SSIS orchestration
  CompanyX_Control_Run.dtsx is a standalone SQL Server 2022 package.
  Four success-dependent Execute Process Tasks: prepare, simulate, publish, process.
  Each runs Python -B -X utf8 <WorkerPath> --stage <stage>
    --request <RequestPath> --run-folder <RunFolder>.
  Package variables, namespace User:
    RequestPath, RunFolder, WorkerPath, PythonExecutable, WorkingDirectory.
  DTExec override form (one argument after /SET):
    \Package.Variables[User::RunFolder].Properties[Value];D:\...\job
  Supply arguments as a process argument list, not a shell command string.
  PythonExecutable defaults to the existing frozen demo .venv Python.
  No SSIS project or package under the frozen demo is edited.
  No successful later stage runs after a failed preceding stage.

Scoped publication API (historical selected-cohort backend)

  Reconstructs the request from the immutable base before generating canonical
  files; validates runtime, input, spec, valuation, manifests and every table.
  ONLY database CompanyX_MOLAP_Source_20261105 on localhost is allowed.
  Original source CompanyX_Demo is read-only for this workflow.
  PublishScoped.sql is derived from SHA-pinned original native Publish.sql.
  Original 9-fact typed comparisons, FK checks, event/quantity reconciliation,
  complete daily grids and KPI checks remain inside one transaction.
  All new dimensions/scenarios, facts, ETL proof and ControlRunScope commit
  together. Any failure rolls back the complete publication.
  Existing runs are not rewritten; before/after counts and row checksums are
  checked in the transaction. These checksums are not cryptographic hashes.
  RunCode replay compares all 9 fact tables exactly and returns ALREADY_LOADED.
  Repeating a request with different contents cannot overwrite the unique
  ControlRunScope request identity.
  Source BOM and lead assumptions retain the ORIGINAL frozen cutoff date.
  SELECTED_LINES service is explicitly labelled as a projected-order cohort;
  WHOLE_ORDERS retains all original sibling lines.

    -RunFolder <job>
  Requires job/publication_receipt.json, schema companyx.inquiry.publication.v1,
  database CompanyX_MOLAP_Source_20261105, and candidates list. Each entry has
  candidate_id, artifact_folder and receipt (publisher return value). All must
  match the saved candidate publication receipts and belong to one inquiry.
  Guards copied warehouse + SSAS ownership markers, runs existing read-only
  dynamic source preflight, refreshes the owned canonical cache with existing
  rows guarded by counts/checksums (no ALTER of old views), then ProcessFull
  only on CompanyX_InquirySimulation at localhost\COMPANYXOLAP, requiring its
  CompanyXMOLAPOwner annotation value companyx-control-20261105.
  No deployment/Alter is issued and no previous MOLAP output file is replaced.
  Logs and each receipt go to job/process-attempts/<timestamp>; the first
  successful receipt is retained as job/process-receipt.json.
